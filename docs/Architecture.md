# 架构演进路线 (Architecture Evolution)

## [V1.0.0] - 静态多线程分块架构
* **技术背景**：单线程顺序读写在面对数 GB 级别的大文件时，无法充分利用现代多核 CPU 的并发能力和底层高速存储设备的物理带宽。
* **核心思想**：将文件分割为N个数据块，预分配好目标文件大小后，利用std::ifstream，std::ofstream配合seekg，seekp实现文件指针偏移，再让N个线程并发读写各个数据块（分块数量和线程数量绑定）

## [V1.1.0] - 动态分块与 I/O 优化
* **技术背景**：V1.0.0 的分块数量硬编码，无法适应不同文件大小和硬件环境；4KB 缓冲区在现代 SSD 上产生过多系统调用开销。
* **核心优化**：
  * 引入自适应分块算法，基于文件大小（32MB 阈值）和 CPU 逻辑核心数动态计算最优分块数量。
  * 将 I/O 缓冲区从 4KB 提升至 4MB，匹配现代 SSD 的经验最优 I/O 粒度。
  * 引入无锁监控面板，实时反馈拷贝进度与速度。

## [V1.2.0] - 存储介质感知与 CLI 改造
* **技术背景**：V1.1.0 版本的多线程并发读写在机械硬盘上会引发频繁磁头寻道导致性能下降；入口函数使用硬编码路径，无法作为通用命令行工具分发。
* **核心改造**：
  * **存储介质感知**：新增 `Utils::IsRotationalDisk` 函数，通过提取设备号并读取 Linux `sysfs` 接口判定存储介质类型，支持跨分区挂载的设备追溯。
  * **HDD 拷贝策略**：引入 `SingleThreadCopy` 单线程顺序拷贝机制，机械硬盘环境下自动切换为单线程模式，缓冲区调整为 1MB，规避并发磁头寻道损耗。
  * **SSD 拷贝策略**：固态硬盘维持多线程并发分块拷贝，缓冲区保持 4MB。
  * **命令行接口**：引入 `getopt_long` 实现 POSIX 标准化命令行接口，支持 `-h/--help` 与 `-v/--version` 标准选项及两个位置参数。
  * **构建系统升级**：启用 C++17 标准与 O2 优化，程序正式命名为 `ufcp`，新增 `make install` 系统级安装支持，提供 `install.sh` 一键安装脚本。
